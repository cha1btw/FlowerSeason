# Передача сайта Flower Season

Цель: Анастасия полностью управляет сайтом сама, со своего компьютера и со своих
аккаунтов. Правки она вносит через Codex, проверяет локально в Docker, публикует
пушем в GitHub, а Vercel сам выкладывает сайт на flowerseason.company.

```
Codex (правки)  ->  Docker на её компьютере (проверка на localhost:3000)
                ->  git push в GitHub  ->  Vercel собирает и публикует сайт
```

## 1. Что есть сейчас и кому принадлежит

| Что | Где | Владелец сейчас | После передачи |
| --- | --- | --- | --- |
| Код | github.com/cha1btw/FlowerSeason (публичный) | Даниил | Анастасия, Даниил помощником (collaborator) |
| Хостинг | Vercel, проект `flower-season` | Даниил (бесплатный план Hobby) | Анастасия |
| Домен `flowerseason.company` | куплен в Vercel, продлевается автоматически, оплачен до 05.10.2027 | Даниил (его карта) | Анастасия (её карта) |
| Telegram-бот | @BotFather | Даниил | Анастасия |
| Секреты (токен бота и т.п.) | Vercel → Settings → Environment Variables | у Даниила | переезжают вместе с проектом Vercel |

Важно знать заранее:

- **В Vercel Hobby нельзя добавить второго человека.** Поэтому «дать доступ»
  на бесплатном плане означает только одно: передать проект на её собственный
  аккаунт Vercel. Альтернатива: план Pro (от $20 в месяц), тогда можно
  пригласить её в команду.
- **Hobby официально только для некоммерческих сайтов.** Это сайт бизнеса.
  Пока трафик маленький, на практике это обычно работает, но по правилам
  Vercel для коммерческого сайта нужен Pro. Решать ей, но знать об этом надо.
- Сейчас коммиты Анастасии попадают в GitHub не с её аккаунта: она не числится
  среди участников репозитория. После передачи всё будет идти от её имени.

## 2. Что делает Даниил (один раз, примерно 30 минут, вместе с ней)

Порядок важен: сначала GitHub, потом Vercel, потом домен.

### 2.1. Подготовка (делает Анастасия)

1. Создать аккаунт на github.com (если нет) и сказать Даниилу свой логин.
2. Создать аккаунт на vercel.com через **«Continue with GitHub»** (тем же
   GitHub-аккаунтом). Тогда Vercel сразу видит её репозитории.

### 2.2. GitHub: передать репозиторий

1. Даниил: github.com/cha1btw/FlowerSeason → **Settings** → внизу **Danger Zone**
   → **Transfer ownership** → ввести её логин.
2. Анастасия: принять передачу в письме от GitHub.
3. Анастасия: в новом репозитории **Settings → Collaborators → Add people** →
   добавить Даниила (чтобы он мог помочь, если что-то сломается).

Старый адрес `github.com/cha1btw/FlowerSeason` GitHub сам перенаправляет на новый,
так что ничего не потеряется.

### 2.3. Vercel: передать проект

1. Даниил: vercel.com → проект `flower-season` → **Settings → General** →
   внизу **Transfer Project** → выбрать её аккаунт.
   Если её аккаунта нет в списке, есть второй способ: сгенерировать код передачи
   (Claude Code может сделать это через Vercel API), она открывает ссылку
   `https://vercel.com/claim-deployment?code=...` в течение 24 часов и принимает проект.
2. Вместе с проектом переезжают деплои и переменные окружения (секреты).
   Деплои на этом время не прерываются.
3. Анастасия: проект → **Settings → Git** → проверить, что подключён репозиторий
   с её аккаунта. Если нет: **Disconnect**, потом **Connect Git Repository** →
   её `FlowerSeason`, ветка production `main`.

### 2.4. Домен flowerseason.company

Домен в Vercel хранится отдельно от проекта и сам не переезжает.

1. Даниил: vercel.com → **Domains** → `flowerseason.company` → **Move** (перенести
   на другой аккаунт/команду) → её аккаунт.
2. Анастасия: проверить в проекте **Settings → Domains**, что
   `flowerseason.company` и `www.flowerseason.company` стоят со статусом
   **Valid Configuration**.
3. Анастасия: в **Settings → Billing** её аккаунта указать карту, иначе домен не
   продлится в октябре 2027.

### 2.5. Telegram-бот

1. Даниил: в @BotFather → `/mybots` → бот → **Transfer Ownership** (если такая
   кнопка есть в вашей версии Telegram), передать Анастасии.
2. Если кнопки нет: Анастасия создаёт своего бота (`/newbot`), новый токен
   вставляет в Vercel → **Settings → Environment Variables** → `TELEGRAM_BOT_TOKEN`,
   потом **Redeploy**. Webhook регистрируется заново (см. README, раздел
   «Telegram bot»).

### 2.6. Проверка, что всё передано

- [ ] Анастасия меняет одно слово на сайте через Codex, пушит в `main`.
- [ ] Через 1-3 минуты в её Vercel появляется новый деплой со статусом **Ready**.
- [ ] Изменение видно на flowerseason.company.
- [ ] Даниил убирает у себя локальную ссылку на Vercel-проект (`rm -rf .vercel`),
      чтобы случайно не задеплоить со своего ноутбука.

## 3. Что ставит Анастасия на свой компьютер

Всё делается одним промптом для Codex: [docs/codex-setup-prompt.md](codex-setup-prompt.md).
Скопируйте промпт целиком в Codex, он сам проверит, что установлено, и скажет,
что поставить руками.

Нужно (бесплатно):

1. **Docker Desktop**: docker.com/products/docker-desktop. Запускает сайт и базу
   данных на компьютере одной командой. После установки его нужно открыть
   один раз и дождаться зелёного статуса «Engine running».
2. **Git**. На Mac: в Терминале `xcode-select --install`. На Windows:
   git-scm.com.
3. **Node.js 22 LTS** (nodejs.org). Сам сайт работает в Docker, Node нужен
   Codex для его собственных проверок.
4. **Codex** (приложение или CLI), вход через её аккаунт ChatGPT.
5. Вход в GitHub на компьютере: Codex предложит `gh auth login` или GitHub Desktop.

## 4. Как работать каждый день

1. Открыть Docker Desktop (он должен работать).
2. Открыть папку проекта в Codex и написать, что поменять. Например:
   «Поменяй цену мастер-класса 20 декабря в тексте на 1900 грн».
3. Codex сам запускает `docker compose up -d`, правит файлы и проверяет.
   Сайт открыт на **http://localhost:3000**. Изменения видны сразу после
   сохранения, перезапускать ничего не надо.
4. Посмотреть результат на localhost, в том числе в узком окне (как на телефоне).
5. Сказать Codex: «закоммить и запушь». Через 1-3 минуты изменение на
   flowerseason.company.

Правило: **ветка `main` = живой сайт.** Мелкие правки текста можно сразу в `main`.
Для крупных изменений попросите Codex сделать отдельную ветку: Vercel даст
ссылку-превью (видно в Vercel → Deployments), проверите её, потом Codex сольёт
ветку в `main`.

Где что лежит (если захочется заглянуть самой):

- тексты сайта: `lib/content.ts`;
- страница конфиденциальности: `lib/legal.ts`;
- фото и видео: `public/media/`.

## 5. Если что-то сломалось

- **Сайт сломался после пуша.** Vercel → проект → **Deployments** → найти
  последний нормальный деплой → **⋯ → Instant Rollback** (или **Promote to
  Production**). Сайт вернётся за секунды, потом спокойно чините код.
- **Деплой красный (Error).** Живой сайт при этом не меняется, работает старая
  версия. Откройте деплой → **Build Logs**, скопируйте ошибку в Codex.
- **localhost:3000 не открывается.** Проверьте, что Docker Desktop запущен, потом
  в Codex: «перезапусти docker compose и покажи логи».
- **Ничего не помогает.** Даниил остаётся collaborator в GitHub и может помочь.

## 6. Что ещё не доделано на живом сайте

- В Vercel нет `DATABASE_URL`: на живом сайте нет базы данных, поэтому
  `/workshops` показывает примерное расписание, а не настоящую запись.
  Чек-лист запуска записи: [docs/booking.md](booking.md), раздел «Going live».
- Страница конфиденциальности (`lib/legal.ts`) помечена как черновик, нужны
  данные ФОП.
