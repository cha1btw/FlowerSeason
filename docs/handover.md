# Передача сайта Flower Season

Цель: Анастасия сама управляет сайтом со своего компьютера. Правки она вносит
через Codex, проверяет локально в Docker, публикует пушем в GitHub, а Vercel сам
выкладывает сайт на flowerseason.company.

```
Codex (правки)  ->  Docker на её компьютере (проверка на localhost:3000)
                ->  git push в GitHub  ->  Vercel собирает и публикует сайт
```

## 1. Кому что принадлежит

| Что | Где | Владелец | Доступ Анастасии |
| --- | --- | --- | --- |
| Код | github.com/cha1btw/FlowerSeason (публичный) | Даниил | collaborator: может пушить |
| Хостинг | Vercel, проект `flower-season` | Даниил (план Hobby) | вход в аккаунт Даниила на её компьютере |
| Домен `flowerseason.company` | куплен в Vercel, продлевается автоматически, оплачен до 05.10.2027 | Даниил (его карта) | через тот же аккаунт Vercel |
| Telegram-бот | @BotFather | Даниил | см. раздел 2.3 |
| Секреты (токен бота и т.п.) | Vercel → проект → Settings → Environment Variables | Даниил | видит в Vercel |

Vercel остаётся на аккаунте Даниила. В Vercel Hobby нельзя пригласить второго
человека, поэтому Анастасия работает под его входом. Отсюда правило:

> **В Vercel трогать только проект `flower-season`.** В этом аккаунте есть и
> другие проекты Даниила (его портфолио, проекты клиентов), а также оплата и
> покупка доменов. Удаление проекта, смена настроек оплаты или покупка
> чего-либо касаются Даниила. Если нужно что-то кроме деплоев, отката и
> переменных окружения `flower-season`, сначала спросить его.

## 2. Что сделать один раз

### 2.1. GitHub: добавить Анастасию в репозиторий

1. Анастасия: создать аккаунт на github.com (если нет) и сказать Даниилу логин.
2. Даниил: github.com/cha1btw/FlowerSeason → **Settings → Collaborators →
   Add people** → её логин. Или в Терминале:
   `gh api -X PUT repos/cha1btw/FlowerSeason/collaborators/<её_логин>`.
3. Анастасия: принять приглашение (письмо от GitHub или
   github.com/cha1btw/FlowerSeason/invitations).

Теперь её коммиты идут от её имени, а не через доступ Даниила.

Репозиторий должен оставаться **публичным**. Сейчас Vercel без проблем деплоит
её коммиты. Если сделать репозиторий приватным, Hobby-план может начать
блокировать деплои от авторов, которые не являются владельцем аккаунта.

### 2.2. Vercel: вход на её компьютере

Уже сделано: Даниил вошёл в свой Vercel в браузере Анастасии. Добавить
vercel.com/cha1btw/flower-season в закладки.

Vercel CLI ей не нужен: деплой идёт сам при пуше в GitHub.

### 2.3. Telegram-бот

Бот создан на Telegram Даниила. Для работы сайта это не мешает: заявки приходят
тем, чьи ID указаны в `ADMIN_TELEGRAM_IDS` в Vercel. Чтобы заявки получала
Анастасия, её Telegram ID должен быть в этом списке (ID бот сам пишет любому,
кто отправит ему `/start`).

Если бот нужно полностью отдать ей: в @BotFather → `/mybots` → бот →
**Transfer Ownership** (если такая кнопка есть в вашей версии Telegram). Если
кнопки нет: она создаёт своего бота (`/newbot`), новый токен вставляется в Vercel →
**Settings → Environment Variables** → `TELEGRAM_BOT_TOKEN`, потом **Redeploy**,
и webhook регистрируется заново (см. README, раздел «Telegram bot»).

### 2.4. Проверка, что всё работает

- [ ] Анастасия меняет одно слово на сайте через Codex, пушит в `main`.
- [ ] В GitHub коммит показан от её аккаунта.
- [ ] Через 1-3 минуты в Vercel → `flower-season` → **Deployments** появился
      новый деплой со статусом **Ready**.
- [ ] Изменение видно на flowerseason.company.

## 3. Что ставит Анастасия на свой компьютер

Всё делается одним промптом для Codex: [docs/codex-setup-prompt.md](codex-setup-prompt.md).
Скопируйте промпт целиком в Codex, он сам проверит, что установлено, и скажет,
что поставить руками.

Нужно (бесплатно):

1. **Docker Desktop**: docker.com/products/docker-desktop. Запускает сайт и базу
   данных на компьютере одной командой. После установки его нужно открыть
   один раз и дождаться зелёного статуса «Engine running».
2. **Git**. На Mac: в Терминале `xcode-select --install`. На Windows:
   git-scm.com.
3. **Node.js 22 LTS** (nodejs.org). Сам сайт работает в Docker, Node нужен
   Codex для его собственных проверок.
4. **Codex** (приложение или CLI), вход через её аккаунт ChatGPT.
5. Вход в GitHub на компьютере: Codex предложит `gh auth login`.

## 4. Как работать каждый день

1. Открыть Docker Desktop (он должен работать).
2. Открыть папку проекта в Codex и написать, что поменять. Например:
   «Поменяй цену мастер-класса 20 декабря в тексте на 1900 грн».
3. Codex сам запускает `docker compose up -d`, правит файлы и проверяет.
   Сайт открыт на **http://localhost:3000**. Изменения видны сразу после
   сохранения, перезапускать ничего не надо.
4. Посмотреть результат на localhost, в том числе в узком окне (как на телефоне).
5. Сказать Codex: «закоммить и запушь». Через 1-3 минуты изменение на
   flowerseason.company.

Правило: **ветка `main` = живой сайт.** Мелкие правки текста можно сразу в `main`.
Для крупных изменений попросите Codex сделать отдельную ветку: Vercel даст
ссылку-превью (видно в Vercel → Deployments), проверите её, потом Codex сольёт
ветку в `main`.

Где что лежит (если захочется заглянуть самой):

- тексты сайта: `lib/content.ts`;
- страница конфиденциальности: `lib/legal.ts`;
- фото и видео: `public/media/`.

## 5. Если что-то сломалось

- **Сайт сломался после пуша.** Vercel → `flower-season` → **Deployments** →
  найти последний нормальный деплой → **⋯ → Instant Rollback** (или **Promote to
  Production**). Сайт вернётся за секунды, потом спокойно чините код.
- **Деплой красный (Error).** Живой сайт при этом не меняется, работает старая
  версия. Откройте деплой → **Build Logs**, скопируйте ошибку в Codex.
- **localhost:3000 не открывается.** Проверьте, что Docker Desktop запущен, потом
  в Codex: «перезапусти docker compose и покажи логи».
- **Ничего не помогает.** Написать Даниилу: он владелец GitHub и Vercel.

## 6. Что ещё не доделано на живом сайте

- В Vercel нет `DATABASE_URL`: на живом сайте нет базы данных, поэтому
  `/workshops` показывает примерное расписание, а не настоящую запись.
  Чек-лист запуска записи: [docs/booking.md](booking.md), раздел «Going live».
- Страница конфиденциальности (`lib/legal.ts`) помечена как черновик, нужны
  данные ФОП.
- Vercel Hobby официально только для некоммерческих сайтов, а это сайт бизнеса.
  Пока трафик маленький, на практике это обычно работает, но по правилам для
  коммерческого сайта нужен Pro.
