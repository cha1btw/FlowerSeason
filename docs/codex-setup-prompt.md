# Промпт для Codex: установка проекта на новый компьютер

Как пользоваться:

1. Даниил должен быть залогинен в свой GitHub и Vercel на этом компьютере
   (см. [handover.md](handover.md), раздел 2.1).
2. Установите и откройте **Codex**.
3. Скопируйте весь текст ниже (между линиями) в Codex.
4. Отвечайте Codex, когда он попросит что-то установить или войти в аккаунт.
   Пароли и коды вводите только сами, в окне браузера или Терминала, не в чат.

---

Привет! Помоги мне настроить на этом компьютере проект моего сайта Flower Season,
чтобы я могла сама вносить правки и публиковать их. Я не программист: объясняй
простыми словами, что делаешь и зачем, и спрашивай меня перед любым действием,
которое что-то удаляет или публикует.

Данные:
- Репозиторий: https://github.com/cha1btw/FlowerSeason (аккаунт брата Даниила,
  я работаю под его входом в GitHub на этом компьютере)
- Папка для проекта: `~/Projects/FlowerSeason`
- Сайт в интернете: https://flowerseason.company (публикуется через Vercel
  автоматически при пуше в ветку `main`)
- GitHub и Vercel: аккаунты брата, там есть его другие проекты. Мы трогаем
  только репозиторий `cha1btw/FlowerSeason` и Vercel-проект `flower-season`. Vercel CLI не
  устанавливай и не используй: деплой идёт сам при пуше в GitHub.

Сделай по шагам и после каждого шага коротко пиши, что получилось:

1. Определи мою операционную систему (macOS или Windows).

2. Проверь, что установлено: `git --version`, `docker --version`,
   `docker compose version`, `node --version` (нужна 22 или новее), `gh --version`.
   Для того, чего нет, дай мне точную инструкцию по установке для моей системы:
   - Docker Desktop: https://www.docker.com/products/docker-desktop/ (после
     установки я открою его и дождусь статуса «Engine running»);
   - Git (на Mac: `xcode-select --install`);
   - Node.js 22 LTS: https://nodejs.org;
   - GitHub CLI: https://cli.github.com (на Mac можно `brew install gh`, если есть
     Homebrew).
   Устанавливать программы с графическим установщиком буду я сама, ты только
   говори, что скачать и где нажать. Дождись, пока я напишу «готово», и проверь
   ещё раз.

3. Вход в GitHub: проверь `gh auth status` (должен быть аккаунт `cha1btw`) и
   что есть доступ к репозиторию (`git ls-remote https://github.com/cha1btw/FlowerSeason`).
   Если входа нет, скажи мне, что нужно попросить Даниила войти: `gh auth login`
   (GitHub.com → HTTPS → через браузер), потом `gh auth setup-git`. Не проси
   пароли и токены и не входи под другим аккаунтом.

4. Настрой git, если ещё не настроен (`git config --global user.name` и
   `user.email`): спроси у меня имя и почту. Коммиты должны быть подписаны
   моим именем, даже если пушим под аккаунтом брата.

5. Спроси меня, нет ли уже проекта на компьютере (я раньше работала с ним в
   Codex). Если есть, используй ту папку и сделай `git pull`. Если нет,
   склонируй репозиторий в `~/Projects/FlowerSeason`. Дальше работай в этой папке.

6. Прочитай `AGENTS.md`, `README.md` и `docs/handover.md`. В `AGENTS.md`
   правила работы с этим проектом, соблюдай их всегда.

7. Проверь, что Docker Desktop запущен (`docker info`). Запусти проект:
   `docker compose up -d --build`. Первый запуск занимает несколько минут.
   Потом смотри `docker compose logs app`, пока не появится `Ready`.

8. Проверь, что сайт работает: открой (или проверь через curl) страницы
   http://localhost:3000/, http://localhost:3000/business и
   http://localhost:3000/workshops. Все должны отвечать без ошибок.

9. Запусти проверки внутри Docker:
   `docker compose exec app npm run typecheck` и
   `docker compose exec app npm test`. Скажи, сколько тестов прошло. Если что-то
   упало, покажи ошибку и объясни простыми словами, но ничего не чини без меня.

10. Файл `.env.local` с секретами для обычной работы НЕ нужен: локально сайт
    работает со своей тестовой базой в Docker. Не создавай его и не проси у меня
    токены.

11. Ничего не коммить и не пушь во время установки.

В конце дай короткую памятку на 5-7 строк:
- как запустить сайт локально, когда я сяду работать;
- как остановить;
- как попросить тебя опубликовать изменения;
- что делать, если сайт в интернете сломался (откат в Vercel → Deployments →
  Instant Rollback).

## Примеры задач для Codex на каждый день

- «Запусти сайт локально и открой главную.»
- «Поменяй на странице /workshops текст про цену: было 1800 грн, стало 1900 грн.
  Покажи, что изменилось, и дай проверить на localhost.»
- «Замени видео в третьей карточке на /business на файл ~/Downloads/new.mp4.
  Сожми его и сделай постер.»
- «Всё проверила, закоммить и запушь в main.»
- «Сделай это в отдельной ветке и дай ссылку-превью из Vercel.»
- «Сайт в интернете сломался после последнего пуша. Помоги откатиться.»
